# シフト管理システム（検査室・栄養科・看護師・放射線室）

## 技術構成
- **フロントエンド/API**: Next.js 14 (App Router) + TypeScript + Tailwind CSS
- **データベース**: Supabase (PostgreSQL)
- **デプロイ**: Vercel

## 部門
- `/`        検査室（自動生成・下書き・確定・印刷）
- `/eiyoka`  栄養科（曜日固定パターン）
- `/nurse`   看護師（内科病棟・夜勤自動割当）← Python+Excel版をWeb移植
- `/radiation` 放射線室（3名・隔週ローテーションの規則ベース生成／CSV・PDF出力）

## 放射線室シフトの初回セットアップ

放射線室機能を使う前に、Supabase で専用テーブルを作成してください（看護師と同様、`radiation_*` で分離）。

1. Supabase ダッシュボード > **SQL Editor** を開く
2. `supabase_radiation_schema.sql` の内容を貼り付けて実行
   - `radiation_staff`（3名：A岸川 / B野田 / C石橋）/ `radiation_requests` / `radiation_shifts` / `radiation_config` が作成されます
3. `/radiation` を開く → 「📋 休み申請・設定」でローテーション基準を実態に合わせる → 「▶ シフトを生成」

### 生成ルール（`radiationShiftEngine.ts`）
- **日曜・祝日**：全員 公休
- **土曜**：隔週で「全員出勤」⇔「全員休み」。全員出勤週は A=8:30-12:30、B・Cの一方が 8:00-12:30(早番)・他方が 8:30-12:30（出勤週ごとに早番交代）
- **平日（月〜金）**：A=8:00-17:00 固定。B・Cは 8:30-17:30 共通で、早番役割を週ごとに交代
- **休み申請**：全休→公休、半休→勤務文字列に `(午前半休)`/`(午後半休)` を付与（マニュアル調整用）

### ローテーションのずれ調整
実際の早番／土曜出勤と生成結果がずれている場合は、「ローテーション設定」タブで
基準月曜・週0の土曜（出勤/休み）・週0の平日早番・最初の出勤週の土曜早番を1つずらして合わせます。
基準日からの経過週数で判定するため、前月の状態を引き継ぐ必要はありません。

### CSV / PDF 出力
- **CSV出力**：当月の表をBOM付きUTF-8でダウンロード（Excelで文字化けしません）
- **PDF出力**：ブラウザ印刷ダイアログ → 「PDFとして保存」（下書き時は透かし表示）

## 看護師シフトの初回セットアップ（重要）

看護師機能を使う前に、Supabase で看護師用テーブルを作成してください。

1. Supabase ダッシュボード > **SQL Editor** を開く
2. `supabase_nurse_schema.sql` の内容を貼り付けて実行
   - `nurse_staff`（35名）/ `nurse_ng_pairs` / `nurse_requests` / `nurse_shifts` / `nurse_shifts_draft` / `nurse_config` が作成され、初期スタッフが投入されます
3. アプリの `/nurse` を開く → 「⚙️ スタッフ・設定」で氏名やルールを調整 → 「▶ シフトを生成」

### 看護師シフトの記号（Excel版と同一）
日 / 夜正 / 夜副 / 非（夜勤明け）/ ✕（公休）/ 年 / 振 / 付 / 看 / 特 ＋ 半日（/年・年/ 等）

### 生成ロジック（旧 generate_shift.py の移植＋日勤人数ルール）
- 夜勤：曜日別の必要人数（設定画面で変更可。初期=月水日2・他3、夜正1名）を満たすよう、夜勤上限・連勤上限・夜勤明け「非」・NG組合せを考慮して割当
- 日勤：**土曜=5名・日曜/祝日=3名**（設定画面で変更可）を固定配置。週末勤務は公平にローテーション
- 平日：人数は固定せず、各看護師の公休(✕)が月の目標日数で揃うよう、平日ごとの公休負荷を平準化して配置（毎日の日勤人数が平均的になる）
- 土日祝で必要人数を満たせない日（希望休・夜勤明けが多い等）は、可能な人数だけ配置して警告を表示
- 連勤上限を超える場合は平日の日勤を公休に振替（土日祝の人数は維持）

### スタッフごとの詳細条件（スタッフ設定タブで編集）
データ駆動なので、コードを触らず画面から追加・変更できます。
- **新人**：夜勤の必要人数（土5・他2〜3）にカウントしない（自動では夜勤に入れない）
- **月公休**：看護師ごとに月の公休数を個別設定（空欄＝全体設定に従う）
- **曜日条件**（各行「条件」ボタン）：
  - 特定曜日は夜勤不可（例：毎週水曜は夜勤に入れない）
  - 毎週○曜は日勤固定（希望休が優先）

新条件を増やす手順：`nurse_staff` への列追加（1人1値）または `nurse_staff_rules` への種類追加（1人に複数）→ エンジン（`nurseShiftEngine.ts`）に判定を1つ足す → UIに入力欄を足す。

## セットアップ手順

### 1. Supabase でDBを作成

1. https://supabase.com にログイン
2. 新しいプロジェクトを作成
3. **SQL Editor** を開いて `supabase_schema.sql` の内容を貼り付けて実行
4. `staff` テーブルの名前を実際のスタッフ名に書き換える

### 2. 環境変数を設定

`.env.local.example` をコピーして `.env.local` を作成：

```bash
cp .env.local.example .env.local
```

Supabase ダッシュボード > Settings > API から以下をコピー：
- `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
- `anon public` キー → `NEXT_PUBLIC_SUPABASE_ANON_KEY`

### 3. ローカルで起動（確認用）

```bash
npm install
npm run dev
```

http://localhost:3000 をブラウザで開く

### 4. GitHub にプッシュ

```bash
git init
git add .
git commit -m "initial commit"
git remote add origin https://github.com/あなたのユーザー名/shift-web.git
git push -u origin main
```

### 5. Vercel にデプロイ

1. https://vercel.com にログイン
2. **New Project** → GitHubリポジトリを選択
3. **Environment Variables** に `.env.local` と同じ値を設定
4. **Deploy** ボタンを押す

## 毎月の使い方

1. ブラウザでアプリを開く
2. **「休み申請を登録」** ページで対象月・スタッフ・区分を入力
3. **「シフトを生成」** ボタンを押す
4. シフト表を確認・手動修正（セルをクリック）
